# JOS: the `.jos` specification, version 2.0.0

`.jos` is a JSON format (RFC 8259) for declaring an intention: what is intended, when it is done, and what is to be avoided, with the metadata needed to identify, verify, compose and execute it. This directory is the package submitted to IANA for the media type below.

- Media type: `application/vnd.jos+json` (one name, in the vendor tree)
- Optional parameter: `version` (`MAJOR.MINOR.PATCH`); `jos.version` is authoritative when the parameter is absent
- Specification: version 2.0.0, tag `v2.0.0`, in `https://github.com/josfox-jos/jos-spec`; version 1.0.0 remains in force at tag `v1.0.0`
- Encoding: JSON text in UTF-8 without BOM; the top-level value is an object; duplicate member names are rejected
- File extensions: `.jos` (primary), `.jos.json` (alternative)
- Fragment identifiers: JSON Pointer (RFC 6901)
- Schema dialect: JSON Schema 2020-12
- Change controller: JOSFOX LLC, jos@josfox.cloud
- Registration status: IANA ticket #1460136, pending

A `.jos` document is data. It is not executable code. Parsing or validating it MUST NOT run anything. A runtime decides whether to act on it and applies its own authorization, sandbox and budgets (`SECURITY.md`).

## Try it

From the root of this repository. The first two commands need only Python 3 and the `jsonschema` package. The others run the reference kernel `jos-core`, which each release candidate attaches as `josfox-jos-core-<version>.tgz` (the version and the sha256 of every attached implementation are in `tck/reference-implementations.lock.json`; the same kernel is published as `@josfox/jos-core` on npm and `jos-core` on PyPI, 2.1.0 at the time of writing). Download the release assets into a folder, here `assets/`. Nothing needs network access after that.

```
python3 -I tck/run.py                                                                        # every valid vector validates, every invalid one fails
python3 -I tools/check-superset.py                                                           # every 1.0.0 vector and example is valid 2.0.0 (one exception: the number rule of Section 2.1)
python3 -I tools/verify-reference-implementations.py --assets assets                         # hashes, offline install, every vector on both kernels
npx -y --package ./assets/josfox-jos-core-<version>.tgz jos-core run examples/atom-hello.jos --json            # an atom: objective, criteria, limits, one receipt
npx -y --package ./assets/josfox-jos-core-<version>.tgz jos-core validate versions/1.0.0/examples/flow.jos --json  # a 1.0.0 document (the version submitted to IANA), read unchanged
```

## Minimal document

```json
{
  "jos": { "version": "2.0.0", "kind": "atom" },
  "meta": { "name": "hello" },
  "intention": {
    "objective": "Print a greeting",
    "success_criteria": ["The text hello is printed"]
  },
  "execution": { "engine": "shell", "run": ["echo", "hello"] }
}
```

Served as `Content-Type: application/vnd.jos+json; version=2.0.0`. This document validates against both `schema/jos.schema.json` and `schema/core.schema.json`, and so do structured criteria such as `{ "exit": 0 }` (SPEC Section 3.3).

## How to validate, without network access

```
python3 -I tools/check-superset.py
python3 -I tools/validate-jos.py --schema schema/jos.schema.json tests/valid-*.json     # every file OK
python3 -I tools/validate-jos.py --schema schema/jos.schema.json tests/invalid-*.json   # every file FAIL
python3 -I tck/run.py
```

Schema validation does not replace the checks that [CONFORMANCE.md](CONFORMANCE.md) assigns to parsers and runtimes (duplicate member names, byte order mark, `integrity.hash`, acyclic dependencies); `tck/run-documents.py` covers them with an implementation.

## Relationship to A2A and MCP

JOS does not replace the Agent2Agent (A2A) protocol or the Model Context Protocol (MCP). A2A defines communication between agents; a JOS document can be carried as structured data in a message, with the media type above. MCP exposes tools, resources and prompts; a JOS document can declare dependencies on MCP capabilities and constraints on their use. JOS declares the contract.

## Releases

Each release is an immutable tag; [CHANGELOG.md](CHANGELOG.md) is the release notes, one section per tag, and [RELEASE_PROCESS.md](RELEASE_PROCESS.md) says what blocks a release. Release candidates are tagged `jos-spec-v<version>-rc.<n>` in the review repository, each one a prerelease that attaches the reference implementations pinned by `tck/reference-implementations.lock.json`; the final release is the tag `v<version>` in the public repository, created by a person (`RELEASE_PROCESS.md`, Tags).
