# Contributing

Contributions to the JOS specification are welcome.

## Before proposing a change

Please determine whether the proposal belongs in:

- the core JOS format;
- a protocol integration profile;
- a runtime implementation;
- a vendor-specific extension.

The core specification SHOULD remain transport-neutral and vendor-neutral.

## Pull requests

A specification pull request SHOULD include:

1. the problem statement;
2. proposed normative behavior;
3. compatibility impact;
4. security considerations;
5. schema changes when applicable;
6. examples and test vectors when applicable;
7. changelog entry.

Normative text SHOULD use BCP 14 terms consistently.

## Issues

Issues are appropriate for:

- ambiguities;
- interoperability problems;
- security concerns;
- proposed new fields or kinds;
- media type questions;
- conformance issues.

## Security reports

Do not disclose exploitable security issues in a public issue when coordinated disclosure is appropriate. Follow `SECURITY.md` and contact the maintainers directly.

## Licensing

By contributing, you agree that your contribution may be distributed under the repository license.
